# rspandoc

A pandoc replacement in Rust.

rspandoc accepts pandoc's command line and, for what it supports, produces
the same document pandoc 3.7.0.2 does. Where its own choice is as good as
pandoc's it makes its own: code is highlighted with syntect rather than
pandoc's skylighting, and DOCX files use rspandoc's own styles. Every such
difference is defined and checked (see Verification). Input or options
outside what it supports are refused with an error rather than
approximated.

## Principle

Same document, not same bytes. The bar is that someone who switches from
pandoc to rspandoc cannot tell from the result that anything changed, and
that this can be checked mechanically against pandoc:

- HTML is pandoc's byte for byte, except the token spans inside
  highlighted code. The markup around them, the token classes and the
  highlighting stylesheet are pandoc's, so pandoc-styled pages keep
  working.
- DOCX is the same document as pandoc's when both are read back by
  pandoc's DOCX reader.
- Anything that cannot meet that bar is refused, not approximated.

## Pipeline

1. `src/markdown/` reads pandoc's Markdown into the tree in `src/ast.rs`,
   refusing constructs it does not implement rather than misreading them.
1. `src/lua.rs` runs `--lua-filter` scripts over the tree.
1. `src/html.rs` turns the tree into a layout document whose break points
   are those of pandoc's HTML: spaces between words and before a tag's
   attributes, never inside code. Code blocks in a language there is a
   syntax for are highlighted by `src/highlight.rs` (syntect, with bat's
   syntax definitions through two-face), which maps syntect's TextMate
   scopes onto pandoc's token classes.
1. For `--standalone`, `src/template.rs` renders pandoc's `default.html5`
   template (in `data/templates/`) around the body.
1. `src/layout/` lays the result out at 72 columns.
1. For `--embed-resources`, `src/embed.rs` re-tokenizes the page, inlines
   linked stylesheets, and compacts stylesheet text the way pandoc does.

For `--to docx`, `src/docx.rs` writes the tree as WordprocessingML with
pandoc's style names, using rspandoc's own style sheet
(`data/docx/styles.xml`, plus a character style per token type) and
numbering, and packs it deterministically.

## Provenance

The layout engine (doclayout), template language (doctemplates), HTML
tokenizer and renderer (tagsoup) and the width and entity tables are ported
from BSD-3-Clause libraries, whose notices are in `THIRD-PARTY-NOTICES.md`;
the tables are generated by `scripts/gen-width-tables.py` and
`scripts/gen-entities.py`; the highlighting stylesheet follows
skylighting's (BSD-3-Clause). The syntax definitions syntect uses carry
their own MIT and Apache-2.0 licences, listed in
`THIRD-PARTY-SYNTAXES.md`. pandoc itself is GPL, so the Markdown reader,
the HTML writer and the embedding rules are written from pandoc's
documentation and from probing its output, not from its source.

## Verification

`scripts/diff-pandoc.py` runs pandoc and rspandoc with the same arguments
over a list of files and reports each output that differs, with its first
differing line. For HTML, highlighted code blocks on both sides are first
turned back into the plain blocks pandoc writes for a language it does not
know, so the code's text is compared but not its colouring. With their real build arguments, the 678 documents of
teaching-syllabi (including its Lua filter), the 68 of business-syllabi and
the CVs in data all match; for DOCX the comparison (`--docx`) is of both
files read back by pandoc's DOCX reader, since rspandoc's styles are its
own.

`tests/golden/` keeps pandoc's output for the cases that took probing to
get right, so the test suite guards them without pandoc installed. Its
expected files come from pandoc and are regenerated with it, never edited.
rspandoc's own outputs, where they are deliberately not pandoc's (DOCX
parts, `highlight/expected.html`), are recorded after review and
regenerated with rspandoc when a change to them is intended.
